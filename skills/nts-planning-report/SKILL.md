# 국세청 기획보고서 작성 스킬

## 역할

사용자는 국세청 혁신정책담당관실 혁신팀장이다. 국세청 전체를 대표해 윗선(대통령실, 국무조정실, 국세청장)에 올라가는 문서를 만든다. 이 문서의 특징은 세 가지다.

- 재료는 각 국실이 보내온 1차 자료다. 국실 자료는 자기 부서 관점이라 톤·수준·형식이 제각각이고, 국세청 전체 관점의 논리로 다시 엮어야 한다.
- 읽는 사람은 상위 기관이다. 국세청이 국정기조와 대통령 강조사항을 어떻게 뒷받침하는지가 문서의 뼈대가 된다. 국세행정 실무 내용만 나열하면 실패한 문서다.
- 양식과 워딩이 거의 고정돼 있다. 과거 문서가 정답지다. 새로 창작하지 말고 기존 문서의 구조와 표현을 재사용한다.

따라서 이 스킬의 핵심은 "요약"이 아니라 "맥락에 맞게 다시 엮기"다. 꼭지(소제목 단위)를 어떤 논리로 세우고, 국실 자료를 어떤 꼭지 아래 배치하며, 각 문장을 지금 시점의 상위 메시지에 맞는 워딩으로 바꾸는 작업이다.

## 자료 위치

| 자료 | 위치 | 용도 |
|---|---|---|
| 기존 보고서 코퍼스 | 사용자 Google Drive `NTS_보고서_코퍼스` 폴더(유형별 하위 폴더). 검색 방법은 `references/corpus-drive.md` | 양식·꼭지 구조·워딩 학습 |
| 문체·기호 규칙 | `references/style-guide.md` | 개조식 작성 규칙 |
| 문서 유형별 뼈대 | `references/doc-types.md` | 꼭지 설계 출발점 |
| 현재 국정 맥락 | `references/context-current.md` | 지금 강조할 메시지 |
| 실시간 이슈 수집 방법 | `references/context-sources.md` | 검색 소스와 우선순위 |
| 워딩 번역표 | `references/wording-map.md` | 국정기조 표현을 국세청 과제 표현으로 |
| 교정 체크리스트 | `references/review-checklist.md` | 제출 전 점검 |
| 파일 읽기·생성·검수 | `references/kordoc.md` | HWP 읽기, HWPX 생성, 공문서 검수 |

코퍼스는 Google Drive 커넥터로 읽는다. 1단계에서 문서 유형이 정해지면 `references/corpus-drive.md`를 읽고 해당 유형 폴더에서 참고 문서를 고른다. Drive를 쓸 수 없을 때만 코워크 프로젝트 지식이나 사용자가 붙여 넣은 문서로 대신한다.

## 작업 순서

작업은 아래 6단계로 진행한다. 사용자가 "그냥 바로 써줘"라고 하면 3단계 확인을 생략하고 끝까지 간다. 그 외에는 3단계에서 한 번 멈춰 꼭지 구조를 확인받는다. 꼭지 구조가 틀리면 그 뒤 작업이 전부 헛수고라서다.

### 1단계. 과업 식별

사용자 요청을 아래 다섯 유형 중 하나로 분류하고, `references/doc-types.md`에서 해당 유형의 뼈대를 읽는다.

1. 대통령 업무보고
2. 범부처 추진과제 대응 국세청 과제 발굴
3. 정부업무평가 대응자료
4. 국세행정 운영방안
5. 수시 기획보고(청장 지시, 국정감사 대비, 현안 보고 등)

분류가 애매하면 사용자에게 한 줄로 묻는다. 함께 확인할 것: 보고 대상(대통령실·국조실·청장·차장), 분량(장수), 마감, 출력 형식(기본 HWPX, 그 외 붙여넣기용 텍스트).

### 2단계. 맥락 스캔

문서를 쓰기 전에 "지금 무엇을 강조해야 하는가"를 먼저 정한다. 순서는 우선순위다. 위가 아래를 이긴다.

1. 대통령 발언·지시(국무회의, 수석보좌관회의, 현장 방문)
2. 국정과제·국정기조
3. 국무조정실·기재부 지침(평가 지표, 업무보고 작성 지침)
4. 국세청장 메시지(취임사, 전국 세무관서장 회의, SNS, 간부회의)
5. 사회 이슈(세정 관련 여론, 국회 지적, 언론 보도)

방법:

- `references/context-current.md`를 읽는다. 사용자가 주기적으로 갱신하는 스냅샷이다. 작성일이 2주 이상 지났으면 사용자에게 갱신 여부를 묻는다.
- 웹 검색이 가능한 환경이면 `references/context-sources.md`의 소스와 검색어로 최근 2~4주 발언을 확인한다. 검색이 안 되면 사용자에게 최근 청장 메시지나 국무회의 내용을 붙여 달라고 한다.
- 사용자가 자료를 붙여 넣으면 그것이 최우선 소스다.

산출물: "이번 문서의 강조 포인트" 3~5줄. 각 줄은 "상위 메시지 → 국세청에서 받는 방식" 형태로 쓴다. 예: "AI 대전환(대통령·청장 공통 강조) → 홈택스 AI 서비스, AI 세무조사 선정을 앞세우고 '국민 체감'을 서술어로". 이 메모를 사용자에게 먼저 보여 준다. 문서 전체의 방향이 여기서 결정된다.

### 3단계. 1차 자료 정리와 꼭지 설계

국실 자료가 파일(HWP·HWPX·PDF·XLSX)이면 `references/kordoc.md`대로 kordoc으로 Markdown으로 읽는다. 납세자 정보 등 개인정보가 보이면 먼저 가린다.

국실 자료를 받으면 바로 쓰지 말고 먼저 표로 정리한다.

| 국실 | 과제명 | 핵심 내용(1줄) | 수치·근거 | 연결되는 상위 메시지 | 비고(중복·누락·수준 미달) |
|---|---|---|---|---|---|

이 표가 중요한 이유: 국실 자료는 자기 과제를 크게 보이게 쓴다. 전체 관점에서 보면 두 국이 같은 내용을 다르게 부르거나, 상위 메시지에 꼭 필요한 과제가 비어 있거나, 수치 근거 없는 주장이 섞여 있다. 표로 펼쳐야 보인다.

표를 만든 뒤 꼭지를 설계한다.

- 뼈대는 `references/doc-types.md`의 유형별 구조에서 출발한다.
- 꼭지 제목은 코퍼스의 같은 유형 문서에서 제목 패턴을 가져온다. 코퍼스에 "○○ 강화로 △△ 실현" 식 패턴이 있으면 그 패턴을 따른다.
- 1차 자료를 꼭지 아래 배치한다. 어느 꼭지에도 안 들어가는 자료는 버리거나 "기타"로 두지 말고, 상위 메시지와 연결할 수 있는지 한 번 더 본다. 연결이 안 되면 사용자에게 뺄지 묻는다.
- 꼭지에 들어갈 자료가 없으면 "자료 요청 필요" 표시를 남긴다. 임의로 내용을 지어내지 않는다.

여기서 멈추고 사용자에게 꼭지 구조(제목 + 각 꼭지에 들어갈 과제 목록)를 보여 준다. 사용자가 "바로 써줘"라고 한 경우는 생략한다.

### 4단계. 작성

꼭지 확정 후 본문을 쓴다. 꼭지 하나씩 쓰고, 꼭지마다 아래를 지킨다.

- Drive 코퍼스에서 같은 유형 최신 문서 1편과 같은 주제 문서 1편을 읽고, 그 문서의 문장 구조와 서술어를 따른다. 코퍼스에 있는 표현이 새로 만든 표현보다 항상 우선한다. 3단계 꼭지 설계 때 이미 읽었으면 다시 읽지 않는다.
- `references/style-guide.md`의 기호 위계, 종결 형식, 숫자·법령 표기를 따른다.
- 국실 자료의 표현은 `references/wording-map.md`로 상위 메시지 워딩에 맞춘다. 예를 들어 국실이 "전산 고도화"라고 쓴 것을 상위 메시지가 "AI 대전환"이면 "AI 기반 ○○ 전환"으로 올린다. 단, 실제 내용이 AI가 아닌데 AI로 포장하지 않는다. 과장은 나중에 국회나 평가에서 되돌아온다.
- 수치는 국실 자료에 있는 것만 쓴다. 없는 수치는 "( )"로 비워 두고 자료 요청 목록에 올린다.
- 각 꼭지의 첫 문장은 "왜 이 과제가 상위 메시지에 필요한가"를 담는다. 둘째 문장부터 "무엇을 한다"다. 국실 자료는 대개 둘째 문장만 있다. 첫 문장을 만드는 것이 총괄부서의 일이다.

### 5단계. 교정

원고 Markdown을 kordoc `lint --gate`로 먼저 기계 검수한다(`references/kordoc.md`). 그다음 아래 체크리스트로 사람 기준 검수를 한다. 기계 검수는 표기법을 잡고, 체크리스트는 상위 메시지 정합과 리스크를 잡는다.

`references/review-checklist.md`를 꺼내 항목별로 점검한다. 특히 아래 셋은 반드시 본다.

- 상위 메시지와 어긋나는 문장이 없는가(예: 세무조사 완화 기조인데 "조사 강화"가 튀어나옴).
- 국실 간 중복·모순이 없는가(같은 수치가 두 꼭지에서 다르게 나옴).
- 과장·단정이 없는가("완전 해소", "전면 차단" 같은 표현).

### 6단계. 출력

기본 출력은 kordoc으로 만든 HWPX 파일이다. 한글에서 바로 열린다.

- 원고는 `references/kordoc.md`의 Markdown 규칙으로 쓴다. 부호(□ ○ -)를 직접 치지 않고 들여쓰기로 위계를 표시한다.
- Drive `00_서식견본`에 맞는 견본 HWPX가 있으면 `--template`으로 그 서식을 쓴다. 없으면 문서 유형별 프리셋에 `--agency 국세청`을 쓴다.
- 만든 뒤 `lint --numbers`로 수치를 대조하고, `validate`로 파일 구조를 확인한다.
- kordoc을 쓸 수 없는 환경이면 같은 원고를 개조식 텍스트로 내고 kordoc 설치를 안내한다.

사용자가 텍스트만 원하면 텍스트로 낸다. 출력 끝에 아래를 붙인다.

- 참고 문서(읽은 Drive 코퍼스 파일명)
- 자료 요청 목록(비워 둔 수치, 자료 없는 꼭지, 확인 필요한 사실)
- 판단이 필요한 지점(워딩 선택 대안, 뺀 자료와 이유)

## 하지 말 것

- 1차 자료에 없는 사실, 수치, 사례를 만들어 넣지 않는다. 비워 두고 표시한다.
- 상위 메시지에 맞추려고 실제 과제 내용을 다른 것처럼 포장하지 않는다. 연결이 약하면 약하다고 말한다.
- 코퍼스 문체를 무시하고 일반적인 "좋은 글"로 쓰지 않는다. 이 문서는 문학이 아니라 양식이다.
- 문서에 대외비 표시나 개인정보가 섞여 들어온 1차 자료를 그대로 출력에 옮기지 않는다. 발견하면 사용자에게 알린다.

## 코퍼스가 비어 있을 때

Drive 폴더가 비어 있거나 HWP 파일만 있어 읽을 문서가 없으면 `references/style-guide.md`와 `references/doc-types.md`만으로 작성하되, 출력 앞에 "코퍼스 없이 일반 정부 보고서 양식으로 작성함"이라고 밝힌다. 그리고 사용자에게 과거 문서 3편 이상을 docx 또는 pdf로 Drive 유형 폴더에 올려 달라고 한 번 권한다. 문체 재현 품질이 크게 달라진다.
