# 국세청 기획보고서 작성 스킬

이 스킬은 「보고서 브레인」이 쓰는 방식이다. 판단 방식·문체·뼈대·충돌 규칙은 이 파일에 없다. 브레인의 버전 스냅샷에 있다. 이 파일은 브레인을 어떻게 읽고, 자료를 어떻게 모으고, 결과를 어떻게 내는지만 정한다.

사용자는 국세청 혁신정책담당관실 혁신팀장이다. 국실 1차 자료를 국세청 전체 관점으로 다시 엮어 상위 기관(대통령실·국조실·청장)에 올리는 문서를 만든다.

## 브레인 위치

Google Drive `NTS_보고서_브레인` 폴더. Google Drive 커넥터로 읽는다.

| 항목 | ID |
|---|---|
| 브레인 루트 폴더 | 1YooagVBGn9ZO1NlanaAo3VszQXBaiFbG |
| 색인 문서 `_index` | 루트 폴더 안. 모든 브레인 문서의 파일 ID 목록 |

- 항상 `_index`를 먼저 읽어 파일 ID를 확정하고 개별 문서를 읽는다. 폴더 목록을 뒤지지 않는다.
- 루트 ID로 못 찾으면 제목으로 찾는다: `mimeType = 'application/vnd.google-apps.folder' and title = 'NTS_보고서_브레인'`, 그 안에서 `title = '_index'`.
- 브레인 원문 코퍼스(과거 보고서 원본)는 `NTS_보고서_코퍼스` 폴더에 따로 있다. 노트로 부족할 때만 원문을 연다. 방법은 `references/corpus-drive.md`.

## 절차

### 0. 브레인 읽기 (필수)

1. `_index`를 읽는다.
2. `synthesis/보고서브레인`의 frontmatter `version` 값 X를 확인한다.
3. `synthesis/versions/vX` 스냅샷을 읽는다. 이것이 이번 작업의 판단 스펙이다(판단 프로세스, 유형별 뼈대, 문체 규칙, 하지 않는 것).
4. 가변 문서(`보고서브레인`)에만 있고 스냅샷에 없는 변경은 적용하지 않는다. 흡수 중인 상태로 본다.
5. `synthesis/conflict-rules`를 읽는다.
6. 브레인 문서를 하나도 못 읽으면 쓰지 않는다. 경로 오류를 보고하고 멈춘다. 브레인 없이 추측으로 문체를 재구성하는 것을 금지한다. 사용자가 "브레인 없이 그냥 써"라고 하면 그때만 일반 정부 보고서 양식으로 쓰고, 결과 머리에 "브레인 미적용"이라고 적는다.

### 1. 과업 식별

요청을 스냅샷의 문서 유형 중 하나로 분류한다. 애매하면 한 줄로 묻는다. 함께 확인할 것: 보고 대상, 분량, 마감, 출력 형식(기본 HWPX).

### 2. 맥락 스캔

"지금 무엇을 강조해야 하는가"를 먼저 정한다. 우선순위는 스냅샷의 규칙을 따른다. 읽을 것:

- 브레인 `context/context-current`: 사용자가 갱신하는 현재 국정·청장 메시지 스냅샷. 작성일이 2주 이상 지났으면 갱신 여부를 사용자에게 묻는다.
- 브레인 `lenses/lens-상급기관`: 이번 유형에 해당하는 상급기관 지침 요구사항.
- 브레인 `lenses/lens-청장`: 현 청장의 키워드와 표현.
- 웹 검색이 되면 `references/context-sources.md`의 소스로 최근 2~4주 발언을 확인한다.
- 사용자가 붙여 넣은 자료가 최우선이다.

산출: "이번 문서의 강조 포인트" 3~5줄을 사용자에게 먼저 보여 준다.

### 3. 근거 노트 고르기

`_index`의 문서 노트 목록에서 필요한 것만 고른다. 전부 읽지 않는다.

- 같은 유형의 최신 노트 1~2개: 뼈대와 꼭지 패턴의 기준.
- 같은 주제의 노트 1개: 해당 분야 워딩의 기준.
- 유형별 교차 노트(`xref-…`)가 있으면 같이 읽는다.
- 노트에 `era: 전 정부·전임 청장`이 붙은 문서는 양식만 참고하고 키워드·슬로건은 가져오지 않는다.
- 노트의 `[추정]` 항목은 근거로 쓰지 않는다.

### 4. 1차 자료 정리와 꼭지 설계

- 국실 자료가 파일이면 `references/kordoc.md`대로 kordoc으로 읽는다. 개인정보가 보이면 먼저 가린다.
- 스냅샷의 판단 프로세스대로 자료를 표로 펼치고, 꼭지를 설계한다. `lenses/lens-국실`의 흔한 결함 목록으로 국실 자료를 점검한다.
- 충돌(예: 청장 표현과 상급기관 지침 문구가 다름)이 생기면 `conflict-rules`로 해소하고 규칙 ID(CR-NN)를 메모한다. 규칙이 없으면 평균 내지 말고 갈리는 지점을 사용자에게 보여 준다.
- 꼭지 구조(제목 + 꼭지별 과제)를 사용자에게 보여 주고 확인받는다. "바로 써줘"면 생략한다.

### 5. 작성

스냅샷의 문체 규칙과 3단계에서 고른 노트의 문장틀·서술어로 쓴다. 노트에 있는 표현이 새로 만든 표현보다 우선한다. 수치는 1차 자료에 있는 것만 쓰고, 없으면 "( )"로 비운다.

### 6. 교정

1. kordoc `lint --gate`로 기계 검수(`references/kordoc.md`).
2. 스냅샷의 점검 목록으로 사람 기준 검수. 상위 메시지 정합, 국실 간 중복·모순, 과장 표현은 반드시 본다.

### 7. 출력

기본은 kordoc HWPX. 방법은 `references/kordoc.md`. 출력 머리와 꼬리:

```
brain: vX   (적용한 충돌 규칙: CR-NN, …)

[본문 또는 HWPX 파일]

참고 노트: <노트 이름 목록>
자료 요청: <비워 둔 수치, 자료 없는 꼭지>
판단 필요: <워딩 대안, 뺀 자료와 이유, 규칙 없는 충돌>
```

## 학습

새 보고서를 브레인에 넣는 일은 이 스킬이 하지 않는다. `report-brain-learn` 스킬이 한다. 사용자가 "이 보고서 학습해", "브레인에 넣어"라고 하면 그 스킬로 넘긴다.

작성이 끝난 뒤 사용자가 결과물을 크게 고쳤다면, 고친 최종본을 코퍼스에 올리고 학습시키라고 한 번 권한다. 브레인이 자라는 주된 통로다.

## 하지 말 것

- 1차 자료에 없는 사실·수치·사례를 만들지 않는다.
- 상위 메시지에 맞추려고 과제 내용을 다른 것처럼 포장하지 않는다.
- 브레인 스펙을 이 파일에 복사해 두지 않는다. 항상 스냅샷에서 읽는다.
- 개인정보·대외비를 출력에 옮기지 않는다.
